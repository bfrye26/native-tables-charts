# Native Tables & Charts 2.0.0 — Advanced Chart Roadmap

Design approved in session 2026-08-17. One combined release (2.0.0) containing
all four roadmap phases; versioning/tagging happens once at the end.

## Phase A — Interaction & Time

### A1. Hover tooltips (all chart types)
- Chart config `enableTooltips` (bool, default false).
- Server adds data-tip attributes to interactive elements: hbar rows, dual
  rows, vbar items, grouped/stacked bars, donut segments + legend items,
  line/scatter circles (`data-tip="Label: Value"`, values via format_value).
- frontend.js: one shared `.ntc-tooltip` div positioned on mouseover of
  `[data-tip]` within `.ntc-chart`, hidden on mouseout. No dependencies.

### A2. Date/time x-axis + Area chart
- Chart config `xColumn` (int, default null → row-order as today).
- New chart type `area` (line with fill below, `chart_line(…, $area=true)`).
- When `xColumn` set on line/area/scatter: x positions scale by timestamp
  (column's sort_value; reuse existing date parsing), min/max from data,
  ~5 "nice" tick timestamps rendered as SVG text + vertical grid lines;
  labels formatted via date_i18n with a smart granularity (auto day/month/
  year by span).

### A3. Reference lines
- Chart config `referenceLines`: array of `{ value: float, label: string,
  color: string }`, max 5, on hbar/dual/vbar/line/area.
- Horizontal/vertical dashed line + right/top-aligned label in chart color
  scale coordinates; values sanitized, colors through safe_css_value.

### A4. Top-N with "Others"
- Chart config `topN` (int, 0 = off), `othersLabel` (string, default
  "Others"). Applied in prepare_chart_rows after sorting: keep first topN
  rows, aggregate remaining numeric value columns into one row.

## Phase B — Review Toolkit

### B1. Radar chart
- Chart type `radar`: rows = axes (labels from labelColumn), valueColumns =
  up to 6 series (polygons). SVG: concentric rings (gridColor), axis spokes,
  polygon per series (series color cycle), labels at spoke ends
  (mutedColor), series legend reused. Config `radarMax` (float, default
  auto = max of data).

### B2. Gauge chart
- Chart type `gauge`: single value from first row / valueColumns[0]. Config
  `gaugeMin` (default 0), `gaugeMax` (default 100), `gaugeFormat` ('auto').
  SVG arc background (gridColor), value arc (primary/highlight if focused),
  needle + value label center, threshold bands from referenceLines entries
  (value → band from 0 to value, color).

### B3. Review Card block pattern
- `register_block_pattern( 'ntc/review-card', … )` in NTC_Plugin: a
  two-column pattern inserting ntc/chart (gauge, "Score") + ntc/chart
  (radar, "Category Scores") + ntc/table (pros/cons). Registered in the
  existing 'ntc-data' category, visible in the pattern inserter.

### B4. Review schema.org
- Chart config `schemaType`: 'off' | 'dataset' | 'review' (default 'off';
  enableSchema legacy key coerced to 'dataset' when true).
- 'review' emits `Product`/`Review` + `aggregateRating` JSON-LD: `name`
  (chart title), `reviewBody` (subtitle), ratingValue from the focused row
  (highlightValues[0]) else first row / valueColumns[0], `bestRating`
  (config `ratingMax`, default 10), `worstRating` (`ratingMin`, 0), author
  = site name. All strings escaped; one `<script type="application/ld+json">`
  per block.

## Phase C — Comparison & Analysis

### C1. Change/delta bars + Dumbbell chart
- Chart type `change`: two value columns (current, previous); delta =
  current − previous; renders signed bars from zero axis with ▲/▼ glyphs
  (reuse --ntc-delta-up/down), value labels show current with delta suffix.
- Chart type `dumbbell`: two value columns per row → horizontal track per
  row with dots at both values, connecting line, value labels; highlight
  support via is_highlight.

### C2. Conditional series coloring
- Chart config `seriesRules`: array of `{ column: int, ranges: [
  { min: float|null, max: float|null, color: string }, … ] }`, max 3 rules.
- Applied server-side wherever fills are chosen (hbar/vbar/grouped/stacked/
  line/area points/donut segments): first matching range wins; color
  sanitized via safe_css_value.

### C3. Legend toggles
- Chart config `legendToggles` (bool, default false) for multi-series
  charts. Server marks each legend item `data-series="N"`; chart body gets
  series classes (extend existing `.ntc-series-N`).
- frontend.js: click toggles `.is-series-hidden` on the chart container;
  CSS hides `.ntc-series-N` elements under it; aria-pressed on legend
  buttons.

### C4. Annotations
- Chart config `annotations`: array of
  `{ type: 'marker', at: string (row label), label: string, color }` or
  `{ type: 'region', from: string, to: string, label: string, color }`,
  max 5, line/area only.
- Rendered in SVG: vertical dashed line + top label (marker); translucent
  rect + top label (region). Colors sanitized; labels escaped.

## Phase D — Data Depth

### D1. Post-driven datasets
- `ntc_datasets` gains `source_mode VARCHAR(16) NOT NULL DEFAULT ''` and
  `source_config LONGTEXT NULL` (dbDelta upgrade path).
- Repository: `get_post_source( int $id ): ?array` (mode + decoded config),
  `set_post_source( int $id, string $mode, array $config ): bool`.
- New `includes/class-ntc-posts-query.php`: `rows_for( array $config ): array`
  — config `{ post_type, posts_per_page (cap 200), orderby, order,
  meta_label, meta_value (string), meta_sort, tax, term }`; runs WP_Query
  (posts with the meta keys), maps label column from post title or
  meta_label, value columns from meta_value (array of keys), optional
  meta_sort ordering; output sanitized like import rows.
- Renderer `resolve()`: dataset with `source_mode === 'posts'` fetches rows
  via the query class with a transient cache `ntc_post_source_<id>` (5 min);
  `save_post` flushes it (extend the existing hook).
- Data Library: source mode select (None / Posts) + minimal config form
  (post type, meta keys) for datasets with source_mode 'posts'; the
  remote-CSV form stays for '' mode.

### D2. Small multiples
- Chart type `small-multiples`: one mini sparkline per row (single value
  column), grid `multiplesPerRow` (default 3); reuses sparkline SVG logic
  server-side; labels under each mini chart.

### D3. Heatmap grid
- Chart type `heatmap`: rows × value columns matrix (up to 12 columns),
  color lerp `heatmapLow` → `heatmapHigh` (defaults #ffffff → #624b8e),
  optional `heatmapLabels` (bool, default true) showing values in cells;
  row labels left, column labels top.

### D4. Range brush
- Chart config `enableBrush` (bool, default false) for line/area.
- Server emits `data-x`/`data-v` on each circle. frontend.js overlays two
  draggable handles; on change it crops the visible point set, re-renders
  the polyline path from the data attributes, and updates the x tick
  labels' text from data attributes. No dependency.

## Cross-cutting

- All new config keys default off/false, opt-in via the chart Inspector
  (new panels: "Interactivity" (tooltips, legend toggles, brush),
  "Analysis" (xColumn, topN/othersLabel, referenceLines, seriesRules,
  annotations), "Schema" (schemaType, ratingMin/Max); radar/gauge/small-
  multiples/heatmap configs inside existing panels).
- All colors through safe_css_value; all labels escaped; SVG attributes
  numeric; no new dependencies, no jQuery; charts remain server-rendered
  and readable without JS (interactive layers are enhancements only).
- Accessibility: tooltips duplicated in aria-labels (already present on
  rows/points); legend toggles use buttons with aria-pressed; brush is
  pointer + keyboard (arrow keys adjust handles).
