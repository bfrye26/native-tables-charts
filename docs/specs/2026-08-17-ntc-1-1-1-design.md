# Native Tables & Charts 1.1.1 — Picker List & Migration Timeout Fixes

Design approved in session 2026-08-17.

## Goals

1. Replace the dataset/view picker's floating-button boxes with a proper
   selectable list (select + confirm; double-click picks instantly).
2. Eliminate League Table migration/XML-import timeouts with two layers:
   batched multi-row inserts (root cause) and browser-driven chunked post
   conversion with auto-resume (content phase).
3. Ship as 1.1.1 with changelog, release, and tag.

## 1. Dataset picker list

- `DatasetPicker` (assets/js/block-editor.js) gains a `selected` state
  `{ kind: 'view'|'dataset', item }`.
- Sections unchanged: Synced views (filtered by block type) and Reusable
  datasets, each rendered as a list of full-width rows (radio dot + name +
  row-count meta). Click selects (highlighted row, single selection);
  double-click picks immediately; footer has Cancel + primary
  "Use selection" (disabled until a row is selected).
- Search field, spinner, and empty states unchanged.
- CSS: new `.ntc-picker-list` / `.ntc-picker-row` styles in editor.css
  (full-width rows, hover border, selected ring + filled radio dot);
  remove any `.ntc-dataset-picker` grid styles if present.

## 2. Batched multi-row inserts (root-cause fix)

- `NTC_Repository::upsert_rows()` and `patch_rows()` switch from one
  prepared INSERT per row to chunked multi-row statements: 500 rows per
  `INSERT … VALUES (…),(…) ON DUPLICATE KEY UPDATE row_json=VALUES(row_json),updated_at=VALUES(updated_at)`, fully prepared.
- Semantics unchanged (same caps, same sanitization, same touch_dataset,
  same false-on-query-failure). `replace_rows`, XML import, and the editor
  save path all inherit the speedup (~10k statements → ~20 per dataset).

## 3. Chunked migration + rollback

- `NTC_Migrator::convert_posts()` takes `$offset`/`$chunk` (clamped 1–1000,
  default 200): counts candidate posts, fetches one ordered page by ID
  (`LIMIT %d OFFSET %d`, prepared), converts ≤ chunk posts, returns
  `posts` (updated), `instances`, `processed` (posts fetched), `total`,
  `errors`.
- `NTC_Migrator::migrate()` keeps table migration + settings sync, runs
  chunk 0 only. New `NTC_Migrator::continue_migration( string $batch_id, int $offset, int $chunk ): array` reads the persisted `ntc_migration_map`
  option and runs only the next conversion chunk; same for
  `NTC_Migrator::rollback( string $batch, int $offset = 0, int $chunk = 200 )`
  (backups page, returns `remaining`).
- Admin flow (`NTC_Admin::handle_actions`): `migration_run` POSTs carry
  hidden `batch_id`/`offset`; progress stored in a user transient
  (`ntc_migration_progress_<uid>`, 1 hour) with `done`, `offset`, `total`,
  and the latest result; `migration_rollback` gets the same treatment
  (`ntc_rollback_progress_<uid>`).
- Migration page: progress notice ("Converting posts… X of Y"), the
  migrate form gets `id="ntc-migrate-form"` and hidden fields; a small
  inline script auto-submits (requestSubmit) ~600 ms after load whenever
  progress exists and is not done — this also resumes an abandoned run.
  The inline confirm only fires when `offset == 0`.
- Dry-run, detect, and XML import unchanged (XML import benefits from the
  batched inserts alone).

## 4. Testing

- Smoke (`tests/ntc-smoke.php`): wpdb stub gains query capture; assert
  `upsert_rows(1, 1001 rows)` issues 3 statements with 500/500/1 value
  tuples; `patch_rows` with 1200 indexed rows issues 3 statements
  (500/500/200). `convert_posts`/`rollback` offset math verified via
  reflection with fake post/backup fixtures in the stub.
- `node --check` on block-editor.js; manual browser checklist for the
  picker (select highlight, disabled confirm, double-click pick, search).
- Full gate: php -l, smoke, node suites, phpcs WordPress-Core 0/0.
