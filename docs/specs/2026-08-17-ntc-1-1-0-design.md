# Native Tables & Charts 1.1.0 — Feature & Best-Practices Release

Design approved in session 2026-08-17. Scope: nine editorial features, nine
best-practice/bug fixes, and a full PHPCS WordPress-Core style pass.

## Goals

1. Close every known functional gap found in the 1.0 audit.
2. Add the approved editorial feature set, all opt-in (default off) so
   existing published blocks are unchanged.
3. Bring PHP into wp.org code-style compliance (WordPress-Core) without
   changing behavior.

## Features (all opt-in via Inspector toggles unless noted)

### 1. Schema.org JSON-LD
- Config: `enableSchema` (bool, false) on both blocks.
- Output: `<script type="application/ld+json">` immediately after the block
  wrapper, type `Dataset`, with `name` (chart title / table caption / dataset
  name), `description` (subtitle / dataset description), `dateModified`
  (dataset `updated_at` when dataset-backed, else post modified date), and
  `variableMeasured` built from numeric value columns (`name`, `unitText`).
- All strings escaped (`esc_html`) before `wp_json_encode`.

### 2. Sparkline and delta column types
- New column types in the editor's type dropdown: `sparkline`, `delta`.
- `sparkline`: cell value is comma/space-separated numbers; renders an inline
  SVG polyline (96×28, `currentColor`) plus sr-only raw text.
- `delta`: cell value parsed as signed number (`+12.5`, `-3`, `0`); renders a
  badge with ▲/▼/— glyph and `ntc-delta-up|down|flat` class; colors via CSS
  vars `--ntc-delta-up` / `--ntc-delta-down` in frontend.css.

### 3. Frontend table controls
- Config: `enableSearch` (false), `enablePagination` (false),
  `rowsPerPage` (10, 1–500).
- Server renders the search input and prev/next + "Page X of Y" bar above the
  scroll container; `frontend.js` filters (case-insensitive textContent) and
  paginates the live tbody. Works with visitor sorting (sort mutates the DOM).
- Search input hidden when the table has no rows; pagination bar hidden when
  rows ≤ page size.

### 4. Heatmap color rules
- autoColorRules entries gain `heatmap` (bool, false), column-scoped only
  (UI shows the checkbox for column rules). `background` = low color,
  `color` = high color.
- Renderer computes per-column min/max in one pass over the rows; numeric
  cells get an interpolated background (hex→RGB lerp). Non-numeric cells are
  unstyled.

### 5. Remote CSV/TSV dataset sync
- New `ntc_datasets` columns: `source_url` VARCHAR(2048) DEFAULT '',
  `source_last_sync` DATETIME NULL, `source_error` TEXT NULL (dbDelta via the
  1.0.8 upgrade check).
- Data Library: per-dataset inline URL form + "Refresh now" button + last
  sync/error display (nonce + `ntc_import` cap).
- New `includes/class-ntc-sync.php`: fetch via `wp_remote_get` (timeout 15 s,
  2 MB body cap, http/https only, sslverify on), parse CSV/TSV (parser moves
  here from `NTC_REST`), `replace_rows`, record result. Failures keep old
  rows and store the error.
- WP-Cron `ntc_sync_remote_datasets` hourly; scheduled on activation, cleared
  on deactivate and uninstall.

### 6. Auto dark theme (charts)
- Config: `themeMode` (`fixed` default / `auto`), `darkBackground`,
  `darkTextColor`, `darkMutedColor`, `darkGridColor` (sensible dark
  defaults).
- When `auto`, chart scoped CSS emits a `prefers-color-scheme: dark` media
  block overriding the four neutral vars. Accent colors untouched.

### 7. Frontend export buttons
- Config: `enableExport` (false) on both blocks.
- Tables: "Download CSV" button — frontend.js builds CSV from the rendered
  table; leading `= + - @` cells are prefixed with `'` (formula-injection
  guard).
- Charts: "Download CSV" (hidden copy of the accessible data table is always
  rendered when export is on, even in `disabled` data mode) and, for
  SVG-based chart types only (donut/line/scatter), "Download PNG"
  (inline SVG serialized → canvas 2× scale → `toBlob` download).

### 8. Classic-editor shortcode
- `[ntc_dataset id="5"]` renders a table from dataset 5;
  `[ntc_dataset id="5" view="9"]` renders the synced view's type with its
  config; `type="chart"` renders a chart from the dataset directly. All
  attributes absint/sanitized; output goes through the existing renderer.

### 9. Last-updated caption
- Config: `showUpdatedDate` (false) on both blocks.
- Dataset-backed blocks append "Last updated: <site-formatted date>" from the
  dataset `updated_at` to the table caption (or a caption line when no
  caption is shown) / chart footer.

## Best-practice and bug fixes

1. CSV formula-injection guard in REST `export_data` and JS exports.
2. REST `args` with sanitize/validate callbacks for list/rows/export/preset
   routes.
3. `create_preset`: replace `$wpdb->replace` with conflict check + `-2/-3`
   slug suffix (no silent overwrite).
4. `/ntc/v1/presets` GET: `__return_true` → `can_edit`.
5. `views_create`: 400 when `dataset_id` does not exist.
6. Uninstall: delete orphan `ntc_lt_view_%` options; clear cron.
7. Grid keyboard navigation: arrow-key movement added to `keyNav` (Enter
   behavior unchanged).
8. VERSION-1.0.md: fix stale chart-preset list; document 1.1.0.
9. Full PHPCS WordPress-Core pass (`phpcbf` auto-fix + manual remainder,
   verified with a clean `phpcs` report). JS style unchanged.

## Data model

- `ntc_datasets` gains `source_url`, `source_last_sync`, `source_error`
  (dbDelta, no table rebuild).
- New option-less cron hook `ntc_sync_remote_datasets`.
- No new tables.

## Error handling

- Sync: unreachable/invalid URL → `source_error` set, old rows kept; UI shows
  the error. Non-CSV responses → parse error recorded.
- PNG export: try/catch, status message on failure, no exception surface.
- JSON-LD: only emitted with valid dataset/post context; empty names fall
  back to dataset name or block defaults.
